description: "Of 22 spec formats, agents need only a few: code as the final spec, RFC → implementation plan for features, tests and golden files for verification, and issue-tracker items for everything else."
date: 2026-10-23T14:39:00.000Z

When I began developing a tool for agents, designed to simplify the creation and management of specifications, I conducted research into the various types of specifications that exist. I identified 22 different forms, ranging from "living specs" to "implementation plans." You can find them all in the table below.

Which specification formats should you choose for agent-based development? Clearly, "Formal Models" and "Contract Specs" are not universal solutions. They are best suited for highly specific, constrained scenarios.

The ideal way to maintain a final specification is within the source code itself. It is impractical to separate a vast number of technical details from the actual implementation. Source code describes these details far more effectively than any prose or specialized specification language.

Feature planning can begin with a proposal document (such as an RFC or PEP) and conclude with an "Implementation Plan." This plan is essentially an "Issue-Tracker Item", formatted in a way that is easily consumable by an agent. Tests and "Golden Files" (reference outputs) ensure that the implementation plan has been executed accurately and completely, covering both the "happy path" and various edge cases.

Bugs, as well as deferred ideas and features, are stored as backlog items, which, in practice, take the form of "Issue-Tracker Items".

There are also documents and tools that define engineering practices, but that is a separate topic, I’ll save that for another time.
